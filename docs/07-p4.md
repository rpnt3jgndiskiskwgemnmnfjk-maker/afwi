# P4：バランス調整・難しい CPU・演出

| 項目 | 内容 |
|---|---|
| 文書番号 | AAC-P4-001 |
| 更新日 | 2026-10-31 |
| 版 | アプリ 0.4.0（versionCode 4） |

## 1. 変更点

| 区分 | 内容 |
|---|---|
| 霧を考慮した CPU | すべての強さの CPU が「推定盤面」だけを見て計画を立てる。探知していない地点の敵部隊は取り除き、画面に出る数の目安（少数／多数）から仮の部隊（スタンドオフ・ボックスは長射程ミサイル、それ以外は制空戦闘機）を置く。敵の手札も見えないものとして扱う。P2 の標準 CPU が真の状態を見ていた問題を解消 |
| 難しい CPU | 候補 12 案を、相手の想定計画に対して 5 回ずつ試しに解決して選ぶ（標準は 6 案・3 回） |
| 易しい CPU | 初心者向けに、要域かどうかを考えずに争奪エリアを選び、滑走路を修復しないようにした |
| バランス | S0 の赤のスタンドオフ弾数 4 → 5、S2 の赤の初期の意志 9 → 7（1,000 局の自動対戦で確認） |
| 地図の操作 | 2 本指のピンチで拡大・縮小、1 本指のドラッグで移動、マウスホイールで拡大。ドラッグの直後は地点を選ばない。「＋」「−」「全域」ボタン |
| 演出 | 解決結果を順に表示し、ダイスが転がって止まる。交戦・攻撃のあった地点を地図上で波紋で示す。端末で「動きを減らす」設定のときは静止表示 |
| 計測の仕組み | `npm run balance`（CPU 同士の自動対戦。局数とシナリオを指定できる） |

## 2. 確認結果（2026-10-31）

### 2.1 強さの比較（席を入れ替えて同数、各シナリオ 60 局）

| シナリオ | 標準 対 易しい | 難しい 対 標準 |
|---|---|---|
| S0 | 34 勝 対 1 勝（40 局） | 29 勝 対 21 勝 |
| S1 | 32 勝 対 8 勝（40 局） | 31 勝 対 28 勝 |
| S2 | 26 勝 対 12 勝（40 局） | 33 勝 対 24 勝 |

残りは引き分け。S1 の難しい対標準は差が小さい。

### 2.2 シナリオのバランス（標準同士、各 1,000 局）

| シナリオ | 青 | 赤 | 引き分け | 破局 | 調整 |
|---|---|---|---|---|---|
| S0 | 466（47%） | 414（41%） | 120 | 0 | 赤のスタンドオフ弾数 4 → 5 |
| S1 | 537（54%） | 411（41%） | 52 | 0 | なし |
| S2 | 442（44%） | 505（51%） | 53 | 0 | 赤の初期の意志 9 → 7 |

要件 NFR-07（1,000 局でクラッシュ 0、陣営別勝率 40〜60%）：**3 シナリオとも満たす**。

調整の経過（1,000 局の 1 回目）：S0 は赤 39%、S2 は青 39% で範囲外だった。兵站を増やす案は効果がなかった（S0 の赤はかえって 36% に下がった）ため、S0 は弾数、S2 は意志で調整した。

### 2.3 その他

| 確認 | 結果 |
|---|---|
| 情報の漏れがないこと | 探知していない敵部隊の種類を入れ替えても、易しい・標準・難しいのどの CPU の計画も変わらない（単体テスト） |
| CPU の思考時間（S2、開発環境） | 易しい 平均 2ms、標準 平均 23ms、難しい 平均 54ms・最大 65ms。スマホで 10 倍かかっても要件 NFR-04（2 秒以内）を満たす見込み |
| 単体テスト | 26 件成功（計測用の 2 件は `npm run balance` のときだけ動く） |
| 通しプレイ | S0 を 1 人で両軍、S1 を CPU と対戦して完走。地図の拡大・ドラッグで地点が誤って選ばれないことを確認 |
| Android 版の画面一式 | 外部への通信 0 件、同梱フォント、保存と再開、戻る操作 |
| APK | 0.4.0、約 4.5MB、API 24〜36、権限なし |
